# 設計 — Web版の複数端末ログイン修正

## 原因

`createAuthSession`の有効件数検索が`userId`だけで絞り込み、`clientType`を指定していない。
そのためWebとiOSの有効セッションが同じ10件上限を消費している。

## 変更

1. Webセッション作成時だけ、`clientType: "web"`の有効セッションを数える。
2. iOSセッション作成時はWebセッション上限を検査しない。登録端末数は既存のデバイス登録上限を維持する。
3. 既存の`GET /api/sessions`と`DELETE /api/sessions/{id}`を使うWeb管理パネルを設定画面へ追加する。
4. 現在のセッションは管理パネルで失効させず、既存のログアウト操作を使う。
5. Appleコールバックの409応答を識別し、上限と解除方法を案内する。

## 安全性

- セッション一覧は既存どおりIPアドレス・詳細User-Agentを保存・表示しない。
- 個別失効は認証済み`userId`、CSRF、対象セッションIDで制限する。
- iOSセッションの失効時に紐づくデバイストークンも失効する既存動作を維持する。
- テストには合成ユーザー・合成セッションだけを使う。
