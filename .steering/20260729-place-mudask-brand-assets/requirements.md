# 要求内容 — MUDASKロゴ・キャラクター配置

## 背景・目的

利用者向け名称はMUDASKへ統一済みだが、Web版とiPhoneアプリの画面内では文字表示が中心で、
正式なワードマークとキャラクターがブランド体験に反映されていない。
ユーザー指定の画像を正式アセットとして取り込み、入口と共通ナビゲーションでMUDASKを識別しやすくする。

## 変更・追加する機能の説明

- やること:
  - 指定ワードマークSVGと透明背景キャラクターPNGを、WebとiPhoneの正式なアセット置き場へ配置する。
  - WebのPCサイドバー、モバイル上部バー、サインイン画面にワードマークを表示する。
  - Webのサインイン画面にキャラクターを装飾画像として表示する。
  - iPhoneの初回案内とサインイン画面にワードマークを表示し、初回案内にキャラクターを表示する。
  - 表示サイズ、ダークモード、文字拡大、読み上げ、狭い画面を考慮する。
  - ブランド画像の正本・派生先・使用ルールを`DESIGN.md`と関連する永続ドキュメントへ反映する。
- やらないこと:
  - WebファビコンとiPhone・iPad App Iconの再変更。
  - API、認証、同期、通知、データモデル、判定ロジックの変更。
  - データ中心のホーム、契約、支出、見直し画面へのキャラクター常設。
  - ユーザー指定画像の配色や形状の変更。

## ユーザーストーリー

- 利用者として、Web版とiPhoneアプリを開いたときに同じMUDASKブランドだと分かる状態で使いたい。
- 利用者として、親しみやすさを感じながらも、契約や支出の確認を妨げない画面を使いたい。

## 受け入れ条件

- [x] AC-1: WebのPCサイドバー、モバイル上部バー、サインイン画面に指定ワードマークが表示される。
- [x] AC-2: Webのサインイン画面に指定キャラクターが表示され、320px以上で横スクロールや操作妨害がない。
- [x] AC-3: iPhoneの初回案内とサインイン画面に指定ワードマークが表示され、初回案内に指定キャラクターが表示される。
- [x] AC-4: ワードマークは読み上げでMUDASKと識別でき、装飾用キャラクターは重複して読み上げられない。
- [ ] AC-5: iPhoneのライト・ダーク・高コントラスト・最大Dynamic Type・低い画面・横向きで、画像より主要操作が優先され、Appleサインインボタンまでスクロールして到達できる。
- [x] AC-6: 既存のWebファビコン、App Icon、機能、データ、認証、同期、通知に意図しない変更がない。
- [x] AC-7: アイコン、ワードマーク、キャラクターそれぞれの正本・派生先・使用ルールが`DESIGN.md`、関連する永続ドキュメント、実装で一致する。
- [x] AC-8: Webのlint・型チェック・buildと実行可能な表示回帰、iPhoneの実行可能な静的検査に合格し、Xcodeや実機で未実施の表示検証は合格扱いせず未確認範囲として明記される。
- [x] AC-9: WebとiPhoneで画像に置換しても、MUDASKの識別、ページ見出し、リンク名の読み上げ構造が維持される。

## 制約事項

- 実在のPII・機微データ・資格情報を参照、生成、外部送信しない。
- 指定素材の形状と色は変更しない。ワードマークは透明余白を除くための表示領域調整だけを許容する。
- キャラクターは入口画面に限定し、支出・契約情報より強く見せない。
- Webは静謐なエディトリアルの情報階層を維持する。
- 指定の多色ワードマークはブランド配色の例外とし、画面全体のアクセント色を増やす根拠にはしない。
- iPhoneはSwiftUI標準のDynamic Type、VoiceOver、ライト・ダーク、高コントラストを優先し、画像より本文と主要操作を優先する。
- App IconはApple向けの不透明画像を維持し、透明PNGへ置換しない。
- ユーザーが正式ロゴ・キャラクターとして提供し配置を依頼したため、リポジトリ同梱とアプリ配布に必要な権限を持つ素材として扱う。
