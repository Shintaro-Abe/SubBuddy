# 要求内容 — アプリ名を MUDASK へ変更

## 背景・目的

`SubBuddy` という名称の既存アプリが存在するため、Web版とiPhoneアプリで利用者に見える名称を
`MUDASK` へ変更する。名称以外の機能、データ、認証、同期、通知、開発環境は現状どおり維持する。

## 変更する範囲

- やること:
  - Web の画面、ページタイトル、iOS の画面、ホーム画面表示名を `MUDASK` にする。
  - 名称変更後も既存の機能とデータ互換性を維持する。
- やらないこと:
  - Bundle ID、App Group、Apple Services ID、URL、Cookie名、環境変数、DB名を変更しない。
  - Swift のモジュール名、型名、Xcode のプロジェクト・Target・Scheme、ファイル・ディレクトリ名を変更しない。
  - GitHub リポジトリ名、ローカルのリポジトリパス、過去の `.steering/`、`.audit/`、ADR、成果物名を変更しない。
  - 永続的ドキュメント、README、手順書のプロジェクト名・内部名を変更しない。
  - アイコン、配色、フォント、タグライン、機能、文言の意味を変更しない。
  - App Store Connect、Apple Developer、Render、GitHub など外部サービス上の名称は、このリポジトリ変更では更新しない。

## ユーザーストーリー

- 利用者として、既存アプリと区別できる `MUDASK` という名称で本アプリを使いたい。
- 開発者として、名称変更後も既存環境、データ、認証、通知、テストをそのまま使いたい。

## 受け入れ条件

- [x] AC-1: Web の利用者向け表示とページタイトルに `MUDASK` が表示され、現行画面に `SubBuddy` が残っていない。
- [x] AC-2: iOS の利用者向け画面とアプリのホーム画面表示名に `MUDASK` が表示される。
- [x] AC-3: Bundle ID、App Group、URL、Cookie名、環境変数、DB名、Swift/Xcodeの内部識別子、リポジトリ構造、文書は変更されない。
- [x] AC-4: Web の lint、型チェック、自動テスト、build が合格し、iOS 設定の静的検査で表示名と内部識別子の境界を確認できる。

## 制約事項

- 実在の PII、契約データ、資格情報を参照・生成・外部送信しない。検証には合成データだけを使う。
- 名称の表記は、利用者向けには半角英大文字の `MUDASK` で統一する。
- 互換性を優先し、内部識別子の `SubBuddy` / `subbuddy` / `SUBBUDDY` は維持する。
- Monitor Extensionの表示名 `SubBuddy Monitor` は内部部品名として維持する。
- 既存の未コミット変更には触れない。
