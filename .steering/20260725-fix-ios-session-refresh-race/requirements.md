# 要求内容 — iOSセッション更新競合の修正

## 背景・目的

iPhoneアプリでAppleサインインが完了した直後、ログイン画面へ戻ることがある。
認証済み通信ごとに別の `APIClient` が作られ、同じ更新トークンを並行使用するため、
サーバーが更新トークンの再利用としてセッションを無効化する競合を解消する。

## 変更・追加する機能の説明

- やること:
  - iOSアプリ内の認証済み通信で同一の `APIClient` を共有する。
  - 並行する認証済み通信が1回のセッション更新結果を共有できるようにする。
  - サインイン直後の並行通信を想定した回帰テストを追加する。
- やらないこと:
  - Bundle ID、Apple Developer設定、Web認証方式を変更しない。
  - API仕様、データベース、通知の有効・無効設定を変更しない。
  - ユーザーから見えるMUDASKの名称を変更しない。

## ユーザーストーリー

- iPhone利用者として、Appleサインイン後にログイン状態を維持したい。なぜなら契約情報の読み込みへ進むため。

## 受け入れ条件

- [x] AC-1: iOSの本番コードで、同じAPI接続先に対する認証済み通信が同一の `APIClient` を使用する。
- [x] AC-2: 複数の認証済み通信が同時にセッション更新を必要としても、同じ更新処理を待機し、更新トークンを重複使用しない。
- [x] AC-3: Appleサインイン直後の契約・通知等の並行通信によってログアウト扱いにならないことを自動テストまたは静的境界テストで確認する。
- [x] AC-4: Bundle ID `com.subbuddy.app`、表示名MUDASK、API契約に変更がない。

## 制約事項

- 実在のAppleアカウント、トークン、メールアドレス、契約情報をテストや記録に使用しない。
- テストは合成データのみを使用する。
- Keychainに保存する認証情報の種類やAPIのトークン形式を変更しない。
