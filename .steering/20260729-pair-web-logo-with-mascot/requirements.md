# 要求内容 — Webロゴ右側へのキャラクター配置

## 背景・目的

Web版のサインイン画面ではワードマークが左寄せで、キャラクターが上に独立している。
共通ナビゲーションではワードマークだけを表示している。
サインインのワードマークを中央へ置き、Webの各共通ロゴで右側にキャラクターを添えて、
ロゴとキャラクターを一体のブランド表現として見せる。

## 変更・追加する機能の説明

- やること:
  - Webサインインのワードマーク自体をパネル中央へ配置する。
  - Web内の既存ワードマーク3箇所（サインイン、PCサイドバー、モバイル上部バー）の右側へキャラクターを配置する。
  - キャラクターは小さな装飾画像とし、ナビゲーションや主要操作を圧迫しない。
  - 共通のロゴリンク名、ページ見出し、装飾画像の読み上げ規則を維持する。
  - ブランド画像の配置規則を`DESIGN.md`へ反映する。
- やらないこと:
  - iPhoneアプリ、App Icon、Webファビコン、画像原本の変更。
  - API、認証、データ、同期、通知の変更。
  - ページごとに異なるキャラクターやアニメーションを追加すること。
  - 登録・編集画面など、現在ロゴがない画面へ新しくロゴを追加すること。

## ユーザーストーリー

- Web利用者として、どの主要画面でもロゴとキャラクターを一体のMUDASKブランドとして認識したい。
- サインインする利用者として、中央に整ったロゴを見ながら主要操作へ迷わず進みたい。

## 受け入れ条件

- [x] AC-1: 320・375・1280pxのサインインで、ワードマーク中心とパネル内容領域の水平中心との差が1px以内である。
- [x] AC-2: サインイン、PCサイドバー、モバイル上部バーで、ワードマークの右側に指定キャラクターが表示される。
- [x] AC-3: 320px以上でワードマークとキャラクターの境界矩形が親領域内に収まり、画像が読み込まれ、横スクロール、ナビゲーション重なり、Appleサインインの操作妨害がない。
- [x] AC-4: PC・モバイルのロゴリンクは「MUDASK ホーム」、サインインはレベル1見出し「MUDASK」と識別でき、全キャラクターは読み上げ対象外で、リンクのキーボードフォーカスを視認できる。
- [x] AC-5: 画像原本、iPhoneアプリ、App Icon、ファビコン、認証・データ機能へ意図しない変更がない。
- [x] AC-6: Webのlint・型チェック・単体テスト・buildと、320・340・374・375・1023・1024・1280pxおよびページズーム200%相当の表示・DOM回帰に合格する。
- [x] AC-7: `DESIGN.md`のキャラクター配置規則が実装と一致する。

## 制約事項

- 実在のPII・機微データ・資格情報を参照、生成、外部送信しない。
- 指定素材の形状と色を変更しない。
- キャラクターは装飾として小さく表示し、契約・支出・見直し情報より目立たせない。
- Webの静謐なエディトリアル表現、320px以上、ページ全体を200%相当に拡大した状態、キーボード操作を維持する。
- 640px物理幅を200%相当で表示した320 CSS px条件でも、ロゴと主要操作を切らず横スクロールを出さない。
