# 要求内容 — 初回版通知配信

## 背景・目的

着手前のSubBuddyは更新日、同期状態、新しいサインイン、削除予定、安全上の重要事項を把握できたが、iPhoneアプリには無効化された説明用設定しかなく、通知許可、予約、APNs、アプリ内履歴が未接続だった。利用者がアプリを開き続けなくても必要な時点に気づけるようにしつつ、契約内容をロック画面へ出さず、利用促進目的の通知を増やさない。

本作業では、2026年7月11日のリリース設計と2026年7月23日の`grill-with-docs`で確定した内容を正とする。古いWBSの「基本の更新前通知はv1.1まで保留」は、通知上の判断操作などの拡張だけを指すよう修正する。

## 変更・追加する機能の説明

### やること

- 初回版の通知を、更新日の事前通知、同期失敗、新規サインイン、アカウント削除予定、セキュリティ事故・長期障害の5種類に限定する。
- 更新日前と同期失敗はiPhoneの端末内通知、新規サインイン・削除予定・安全通知はAPNsによるサーバー通知とする。
- 新規サインイン、削除予定、安全通知を、iPhoneとWebの「お知らせ」で確認できるようにする。
- 利用者単位の通知希望と端末単位の配信状態を安全に管理する。
- PostgreSQLの送信待ち、Render Cron、APNs直接送信を使って、再送可能で重複しない配信を実装する。
- 契約に入力した更新基準日を上書きせず、月額・年額の更新予定日を算出する。
- 未完成の通知を本番利用者へ見せない機能フラグと、運用者向け安全配信コマンドを実装する。
- `docs/`、`manuals/`、WBS、テスト監査台帳を現行実装へ合わせる。

### やらないこと

- Web Push、SMS、広告、利用促進、節約訴求、アンケート催促、月次ダイジェストを追加しない。
- 通知上の1タップ判断、トライアル終了通知、自動解約を追加しない。
- Appleサインインから氏名・メールを取得しない。
- 契約名、金額、更新日、利用量、見直し内容をロック画面、APNs payload、運用ログへ出さない。
- 開封、クリック、通知からの行動を追跡しない。
- セキュリティ事故や長期障害を、監視検知だけで利用者へ自動配信しない。

## ユーザーストーリー

- 利用者として、年額契約の更新が近いことを事前に知りたい。見直す機会を逃したくないから。
- 利用者として、一時的な通信失敗ではなく、未送信状態が長く続く場合だけ知りたい。不必要に不安になりたくないから。
- 利用者として、心当たりのない新規サインインを知り、該当セッションを解除したい。アカウントを守りたいから。
- 利用者として、削除予定や重大な安全情報を、OS通知を拒否していても確認したい。データと利用判断に影響するから。
- 利用者として、通知の希望と実際に届く状態を区別して確認したい。「オン」なのに届かない状態を避けたいから。
- 管理者として、機微情報を見ずに配信失敗を調査し、誤った一斉通知と重複配信を防ぎたい。

## 受け入れ条件

- [ ] AC-1: 利用者向け通知は5種類だけで、更新日前・同期失敗は初期オフ、新規サインインのプッシュは初期オンかつ停止可能、削除予定・安全通知のアプリ内表示は停止不可である。
- [ ] AC-2: 年額契約は通知希望を有効にすると更新予定日の7日前10時、月額契約は追加で有効にした場合だけ1日前10時に、通知対象iPhoneから1更新日1回だけ端末内通知される。
- [ ] AC-3: 更新予定日は本人入力の更新基準日と請求周期から算出し、月末・閏日を各月・年の末日に丸め、利用中の契約だけを対象にし、入力値を自動上書きしない。
- [ ] AC-4: 同期失敗は未送信記録が24時間残った場合だけ対象端末へ1回通知し、成功時は予約を取り消し、同じ未解決状態では繰り返さない。
- [ ] AC-5: 初回起動・サインイン直後にOS許可を自動要求せず、更新日付き契約の初回登録後に一度だけ表示する通知案内または設定から、利用者が選んだ場合だけ要求する。
- [ ] AC-6: 設定画面は、未設定、許可確認中、このiPhoneで有効、OS設定で停止中、配信準備中、一時的な問題、このiPhoneでは停止を区別し、停止中はiOS設定を開ける。
- [ ] AC-7: 通知希望は利用者単位、iOS許可・APNsトークン・端末内予約・このiPhoneで受け取る設定は端末単位とし、Webで希望を停止した場合は次回iPhone同期で予約を取り消す。
- [ ] AC-8: Webは通知希望、お知らせ、新規Webセッションの記録、重要未読表示を提供するが、Web Pushを要求・登録・配信しない。
- [ ] AC-9: 最初のアカウント登録を除く新しいiPhone登録またはWebセッション作成を新規サインインとして1回記録し、トークン更新・アプリ復帰・同一セッション再利用では記録しない。
- [ ] AC-10: 新規サインインのAPNsは発生端末以外の通知対象iPhoneへ送り、お知らせには一般的なクライアント種別と時刻だけを表示し、「端末とセッション」から失効できる。
- [ ] AC-11: お知らせは新規サインイン・削除予定・安全通知だけを原則90日保持し、未読件数を設定入口に示し、未読の削除予定・安全通知だけをホーム上部にも表示する。
- [ ] AC-12: 削除予定は、通常アカウントの90・30・7日前、空アカウントの7日前、削除専用コード申請直後・24時間前、TestFlight終了時・7日前に配信し、Apple再認証による即時退会には配信しない。
- [ ] AC-13: 安全通知は自動監視後、管理者が事故ID、定型文、対象件数、配信経路をプレビューして確定した場合だけ配信し、同じ事故IDを重複配信しない。
- [ ] AC-14: 通知用メールアドレスを登録・保存・送信せず、重要連絡はAPNsとアプリ内のお知らせで提供する。
- [ ] AC-15: サーバー通知は、APNsトークン認証、PostgreSQLの送信待ち、5分間隔のRender Cronを使い、送信イベント・経路・対象ごとに冪等で再試行でき、即時対象は次のCron実行まで最大5分で処理を開始する。
- [ ] AC-16: 無効なAPNsトークンは停止し、端末解除・サインアウト・無効応答・完全退会時に配信資格を削除する。
- [ ] AC-17: 通常通知は端末現地時刻の9時から20時に限定し、新規サインインと安全通知だけ即時配信する。Appleの緊急通知権限は要求しない。
- [ ] AC-18: 通知本文、APNs payload、配信記録、ログに禁止情報を含めず、お知らせは原則90日、配信試行記録は30日保持し、開封・クリック・行動を追跡しない。
- [ ] AC-19: 通知全体の機能フラグは初期オフで、資格情報・Cron・移行・5種類の自動試験と実機試験が完了するまで、現行の無効画面を利用可能表示へ変えない。
- [ ] AC-20: iOSはVoiceOver、最大Dynamic Type、44ポイント操作領域、ライト・ダーク、小画面で主要通知操作を完了でき、Webはキーボード、可視フォーカス、200%拡大、360px以上で完了できる。
- [ ] AC-21: 合成データだけを使い、更新日の月末・閏日・時差変更、iOS予約上限、権限拒否、複数端末、順不同・重複、APNs失敗、Cron再実行、削除連鎖、テナント越境拒否を自動・実機で検証する。

## 制約事項

- 実在の契約、利用量、端末トークン、資格情報、本番DBを開発・テスト・証跡で扱わない。
- iPhoneからサーバーへ送る利用情報は既存どおり集計値だけとし、通知のために詳細ログを追加しない。
- 通知文、日数、時刻、保持期間、再試行回数は設定へ外出しし、コードへ散在させない。
- `cloud-testflight`と`production`のDB、APNs環境、暗号鍵を分離する。
- `local` modeは外部配信を行わず、設定不足時に認証や通知を迂回しない。
- APNs秘密鍵と暗号鍵をリポジトリへ置かない。
- iOS 17.4以降、iPhone専用・縦向き、日本語・日本円、日本向け提供の既存方針を維持する。
